# MEGA KHUJAND — заметки для Claude

Продажный сайт ЖК в Худжанде: статический HTML, `css/site.css`, ванильный JS, без сборки. Как устроен сайт — `README.md`; продукт, аудитория и что подтверждено — `PRODUCT.md`; дизайн-система «Выставочный макет» — `DESIGN.md`; что ещё заглушка — `TODO-CONTENT.md`. Для дизайн-работы в проекте есть скилл `impeccable` (`.claude/skills/impeccable`).

## Правила, которые нельзя нарушать

- Сайт только на русском.
- Не выдумывать факты: заглушки не выдавать за правду (цены, наличие, сроки, застройщик — см. `PRODUCT.md`).
- Листы планировок — «Б-1…»; что такое «Б» (секция, блок, корпус) не подтверждено. Не подписывать макет или планировки корпусом.
- Мебель в гипсовом макете иллюстративная (по 3D-видам из листов), не выдавать её за часть проекта.
- Монохромная система: тёплый свет (`--led`) — только «квартира свободна/горит»; никакой латуни, градиентов, свечений.
- Рабочая ветка — `claude/eager-lovelace-ok9mwx` (в `main` этих работ нет).

## Сайт локально

```bash
python3 -m http.server 8080      # открывать через сервер, не file://
```

## Гипсовый макет этажа («раскладушка»)

Главная, секция «Типовой этаж изнутри», и страница планировок («Макет / Схема», «Лист проекта / Макет»). Конвейер:

1. `tools/plans-extract.py` — листы `media/plans/src/*.pdf` → `media/plans/real/` и `js/plans-data.js`. Код квартиры читается из листа, имя файла не важно (лучше латиницей: `b6.pdf`).
2. `tools/model-floor.py` — векторный ключ-план этажа из первого PDF → `media/model/floor.json` (стены, окна, двери, балконы, лестница, лифты, контуры квартир в метрах).
3. `tools/model-furniture.json` — мебель по комнатам, расставлена вручную по 3D-видам из листов (`media/plans/real/<id>-1600.webp`). Формат описан в поле `"_"` файла: комната `room` в метрах `floor.json`, предмет — тип `t`, доли комнаты `u`/`v`, сторона `side`; зеркальная квартира — `"mirror"`. **Для каждой новой квартиры комнаты и мебель нужно вписать сюда** — иначе квартира не обставлена и не горит.
4. `tools/model-render.py all <папка-сырых>` — Blender/Cycles: финальный кадр со светом каждой квартиры (группы света), крупный план каждой квартиры, 80 кадров раскладки. `scene <папка>` сохраняет `model-floor.blend` — открыть в Blender и посмотреть.
5. `tools/model-pack.py <папка-сырых>` — картинки для сайта в `media/model/` и `js/model-data.js` (руками не править). Перед упаковкой удалить старые `media/model/{seq,final-*,light-*,close-*}`.

Окружение (Python 3.11 — под него есть колёса `bpy` 4.5):

```bash
uv venv -p 3.11 .venv && source .venv/bin/activate        # или python3.11 -m venv .venv
uv pip install bpy==4.5.4 shapely numpy scipy pillow pymupdf
python tools/model-render.py scene /tmp/mk-raw             # быстрая проверка, сцена для Blender
python tools/model-render.py all /tmp/mk-raw               # полный рендер
python tools/model-pack.py /tmp/mk-raw
```

Сырые рендеры (PNG, ~150 МБ) держать вне репозитория или в `media/model/raw/` (в `.gitignore`).

Видеокарта выбирается сама: Metal на Mac с Apple Silicon, иначе OptiX/CUDA/HIP, иначе процессор (`MK_DEVICE=CPU` — принудительно процессор). В облаке на 4 ядрах CPU финал и каждый крупный план шли ~8 минут, кадр раскладки ~1 минуту (всё вместе ~2,5 часа); на Metal должно быть в разы быстрее. На ноутбуке во время рендера держать его на зарядке и не давать уснуть (`caffeinate -i …`).

Можно запускать и из самого Blender: `/Applications/Blender.app/Contents/MacOS/Blender -b -P tools/model-render.py -- all /tmp/mk-raw` (тогда `shapely` ставится в Python внутри Blender). Если подключён Blender MCP — удобно смотреть и подбирать свет/камеру в живом окне, но источник правды — скрипты: удачные правки переносить в `tools/model-render.py`.

### Уже найденные грабли

- Пересекающиеся предметы мебели (угловые диваны, Г-образные столешницы) дают в Cycles чёрные пятна из-за совпадающих граней — в `furniture()` у каждого предмета своя высота (`lift`), не убирать.
- Номера комнат на крупных планах проецируются на высоте 2 м (у пола их закрывает ближняя стена санузла); подписи этажей — у левого края плиты на экране (`plate_marks`).
- `model-pack.py` поднимает чёрный фон рендера до графита страницы (`#121416`) и гасит края кадра в него же — CSS-маски на холсте нет специально (дорого при прокрутке). Крупные планы, где квартира мелкая, обрезаются по её тёплому свету.
- Плеер `js/model.js` держит кадры сжатыми (Blob) и расшифровывает (ImageBitmap) только ~15 вокруг текущего; кадры не смешивать — смешивание давало «двойные» этажи и съедало память.
- Сейчас все 5 листов — типовой этаж 3–6, макет — 4 одинаковые плиты. Если придут листы других этажей, `model-floor.py` и стопку в `model-render.py` (`FLOORS`, `scene_base`) нужно научить нескольким типам этажей; дорисовывать этажи без чертежей нельзя.

### Проверка после пересборки

Сайт через `python3 -m http.server`: главная (прокрутка раскладки от 900 px, телефон 390 px — проигрывание один раз, уменьшенное движение — финальный кадр), `plans.html?plan=<id>` для каждой квартиры («Макет» с номерами комнат, «Макет / Схема» на этаже). Консоль без ошибок, axe без нарушений, `.claude/skills/impeccable/scripts/impeccable detect` без новых находок.
