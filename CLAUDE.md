# MEGA KHUJAND — заметки для Claude

Продажный сайт ЖК в Худжанде: статический HTML, `css/site.css`, ванильный JS, без сборки. Как устроен сайт — `README.md`; продукт, аудитория и что подтверждено — `PRODUCT.md`; дизайн-система «Выставочный макет» — `DESIGN.md`; что ещё заглушка — `TODO-CONTENT.md`. Для дизайн-работы в проекте есть скилл `impeccable` (`.claude/skills/impeccable`).

## Правила, которые нельзя нарушать

- Сайт только на русском.
- Не выдумывать факты: заглушки не выдавать за правду (цены, наличие, сроки, застройщик — см. `PRODUCT.md`).
- Листы планировок — «А-1…А-8» и «Б-1…Б-7»; буква — **блок** (со слов архитектора, 2026-10). У блоков Б и В одинаковые типовые этажи; листов В нет, поэтому Б и В показаны вместе («Блоки Б и В · этажи 3–6»), подписи — `BLOCKS` в `tools/plans-extract.py`. Корпусом не подписывать. Взаимное расположение блоков видно только на схеме-миниатюре в листах 1–2 этажей (без размеров между блоками) — плиты макета рядом не ставить без отдельного решения пользователя.
- Дом со слов заказчика (2026-10-04): четыре жилых блока А, Б, В, Г по 18 этажей; 1–2 этажи — торговые помещения, квартиры с 3-го; блок Д — двухэтажный: 1-й этаж детский сад, 2-й фитнес, на крыше спортплощадка (чертежей Д нет). Схема в листах 1–2 этажей с этим расходится (А — 11 этажей, Б/В/Г — 18, Д — 9, в середине двухэтажная парковка) — пока не уточнено, этажность блоков на сайт не писать.
- Лоты (`js/data.js`): блоки А–Г, этажи 3–18; стояк — квартира типового этажа из листов (А-1…А-8; Б-1…Б-7 в блоках Б и В), площадь и экспликация — по листу; выше типовых этажей типовой этаж повторяется (`typical: false`), блок Г без квартир. Статусы, цены, номера, отделка — генератор-заглушка. `js/plans-data.js` подключать раньше `data.js`. «Вид на реку», «угловая», студии и пентхаусы не выдумывать — по листам их нет.
- Первые два этажа (торговые) на сайте — без акцента: владельцы коммерции не целевая аудитория. Не моделировать; только тихий раздел в конце `plans.html` (`#commerce`) и ссылка из легенды квартала на главной.
- Мебель в гипсовом макете иллюстративная (по 3D-видам из листов), не выдавать её за часть проекта.
- Монохромная система: тёплый свет (`--led`) — только «квартира свободна/горит»; никакой латуни, градиентов, свечений.
- Рабочая ветка — `claude/eager-lovelace-ok9mwx` (в `main` этих работ нет).

## Гипсовый макет этажа («раскладушка»)

Главная, секция «Типовой этаж изнутри», и страница планировок («Макет / Схема», «Лист проекта / Макет»). Листов 15, у каждой серии свой типовой этаж — своя **плита**: А-1…А-8 — этажи 3–7 (две лестницы, 4 лифта), Б-1…Б-7 — этажи 3–6. Ключ плиты — серия и этажи (`a-3-7`, `b-3-6`); все квартиры обоих ключ-планов есть в листах. Конвейер:

1. `tools/plans-extract.py` — листы `media/plans/src/*.pdf` → `media/plans/real/` и `js/plans-data.js` (у планировки `floor` — ключ плиты, ключ-план — `media/plans/real/floor-<плита>.svg`). Код квартиры читается из листа, имя файла не важно (лучше латиницей: `a1.pdf`, `b6.pdf`).
2. `tools/model-floor.py` — векторный ключ-план каждой плиты из первого листа серии → `media/model/floor.json`, `plates[<плита>]` (стены, окна, двери, балконы, лестницы, лифты, контуры квартир в метрах; у каждой плиты свои координаты с нулём в центре).
3. `tools/model-furniture.json` — мебель по комнатам, расставлена вручную по 3D-видам из листов (`media/plans/real/<id>-1600.webp`). Формат описан в поле `"_"` файла: комната `room` в метрах плиты своей квартиры, предмет — тип `t`, доли комнаты `u`/`v`, сторона `side`; зеркальная квартира — `"mirror"`. **Для каждой новой квартиры комнаты и мебель нужно вписать сюда** — иначе квартира не обставлена и не горит. Доли считаются от комнаты, уже уточнённой по стенам (`room_rects()` в рендере: грань не дальше 0,35 м), — удобно мерить предметы на 3D-виде рамками и переводить в доли той же комнаты на виде.
4. `tools/model-render.py all <папка-сырых> [плита…]` — Blender/Cycles для каждой плиты в `<папка>/<плита>/`: финальный кадр со светом каждой квартиры (группы света), крупный план каждой квартиры, 80 кадров раскладки. `MK_FLATS=a1,b6` — только эти крупные планы. `scene <папка>` сохраняет по сцене на плиту, `model-floor-<плита>.blend` — открыть в Blender и посмотреть.
5. `tools/model-pack.py <папка-сырых>` — картинки для сайта в `media/model/` и `js/model-data.js` (`plates` и `close`; руками не править). Перед упаковкой удалить старые `media/model/{seq,final-*,light-*,close-*}`.

Окружение (Python 3.11 — под него есть колёса `bpy` 4.5):

```bash
uv venv -p 3.11 .venv && source .venv/bin/activate        # uv: brew install uv; или python3.11 -m venv .venv
uv pip install bpy==4.5.4 shapely numpy scipy pillow pymupdf
python tools/model-render.py scene media/model/raw         # быстрая проверка, сцены для Blender
python tools/model-render.py all media/model/raw           # полный рендер обеих плит
python tools/model-pack.py media/model/raw
```

Сырые рендеры (PNG, ~150 МБ) держать вне репозитория или в `media/model/raw/` (в `.gitignore`).

Видеокарта выбирается сама: Metal на Mac с Apple Silicon, иначе OptiX/CUDA/HIP, иначе процессор (`MK_DEVICE=CPU` — принудительно процессор). На MacBook с M3 (Metal, 10 ядер GPU) финал плиты считается ~20 с, крупный план — 1,5–2 мин, кадр раскладки — 12–17 с; обе плиты целиком (2 финала, 15 крупных планов, 160 кадров) — около 80 минут. В облаке на 4 ядрах CPU финал и каждый крупный план шли ~8 минут, кадр раскладки ~1 минуту. На ноутбуке во время рендера держать его на зарядке (за полный рендер на батарее уходит ~50 % заряда) и не давать уснуть (`caffeinate -i …`).

Можно запускать и из самого Blender: `/Applications/Blender.app/Contents/MacOS/Blender -b -P tools/model-render.py -- all /tmp/mk-raw` (тогда `shapely` ставится в Python внутри Blender). Если подключён Blender MCP — удобно смотреть и подбирать свет/камеру в живом окне, но источник правды — скрипты: удачные правки переносить в `tools/model-render.py`.

### Уже найденные грабли

- Пересекающиеся предметы мебели (угловые диваны, Г-образные столешницы) дают в Cycles чёрные пятна из-за совпадающих граней — в `furniture()` у каждого предмета своя высота (`lift`), не убирать.
- Номера комнат на крупных планах проецируются на высоте 2 м (у пола их закрывает ближняя стена санузла); подписи этажей — у левого края плиты на экране (`plate_marks`).
- `model-pack.py` поднимает чёрный фон рендера до графита страницы (`#121416`) и гасит края кадра в него же — CSS-маски на холсте нет специально (дорого при прокрутке). Крупные планы, где квартира мелкая, обрезаются по её тёплому свету.
- Плеер `js/model.js` держит кадры сжатыми (Blob) и расшифровывает (ImageBitmap) только ~15 вокруг текущего; кадры не смешивать — смешивание давало «двойные» этажи и съедало память.
- Плиты разные по размеру: камера раскладки и финала заданы для плиты Б, для А (шире) расстояние и взлёт этажей масштабируются шириной плиты в кадре (`SPAN` в `use()`); стопка — столько этажей, сколько в подписи ключ-плана (`floors`). Дорисовывать этажи или ставить плиты рядом (их взаимное положение неизвестно) нельзя.
- 3D-вид в листе обрезан контуром квартиры (clip-path `W* n` перед растром): за контуром в растре бывают служебные подписи («Г4», «Г5») и обрывки сцены. `plans-extract.py` закрашивает всё за контуром фоном и кадрирует по нему.
- Подсветка квартиры на ключ-плане в листах А разного цвета (в А-6 — тем же красным, что стрелка входа): ищется как единственная цветная заливка ключ-плана, стрелка входа — только правее `SHEET_X`. В листах А стрелки входа нет.
- Лестницы плиты А повёрнуты: проступи вертикальные, марш идёт вдоль x (`axis` в `floor.json`); промежуточная площадка — там, где на чертеже поворачивает линия хода (`landing`).
- Одноимённые комнаты (два санузла, две спальни) получают номера экспликации по площади, а не по порядку: в зеркальной А-7 санузлы пронумерованы наоборот относительно А-2.

### Первые два этажа (торговые помещения)

Листы 1–2 этажей — `media/plans/commerce/src/<блок>-<этаж>.pdf` (`a-1`, `a-2`, `b-2`, `v-1`, `v-2`, `g-1`, `g-2`; листа 1-го этажа блока Б нет). Если такой лист попадёт в `media/plans/src/`, `plans-extract.py` пропустит его с предупреждением (нет комнатности или 3D-вида) — перенести сюда. `python tools/commerce-extract.py` перерисовывает каждый лист в упрощённую схему `media/plans/commerce/<блок>-<этаж>.svg`: стены и колонны — по тёмно-красной заливке листа, линии — чёрные штрихи от 0,7 pt; оси (пунктир, уходящий за стены к кружкам), короткие штрихи подписей (не касаются стен и длинных линий) и подчёркивания под площадями отбрасываются. Подписи и экспликация в этих листах нарисованы линиями, текстом не читаются: площади залов вписаны в `plans.html` руками по экспликации (у Г экспликация — 694,84 м², а подпись на плане — 685,62; на сайте — экспликация). В рамке листа: заказчик «Элит Сохтмон», проектировщик ЧДММ «Арк Синон» — на сайт без подтверждения не выносить.

### Шахматка «Весь дом ночью» (`building.html`, `js/building.js`)

Четыре башни на графитовом стенде, окно — квартира; нажатие раскрывает блок через View Transitions: этаж — `MK.model3d.floor` с `level(id, sel, hot)` (свет свободных квартир этажа) и `off(id)`, карточка — настоящая планировка. Плоскости рендеров фасада привязаны к блокам условно (`FACADE[].planes[].blk`); сетку окон плоскостей (`cols`, `from`, `to`) менять только вместе с `tools/facade-light.py`. В headless Chrome переход View Transitions может не доиграть — снимать с `prefers-reduced-motion: reduce`.
