# MEGA KHUJAND — сайт жилого комплекса

Продажный сайт ЖК MEGA KHUJAND в Худжанде: ул. Сырдарьинская, 14, на берегу Сырдарьи. Статический HTML, одна общая таблица стилей и небольшой скрипт на страницу — без фреймворка и без сборки. Открывается с любого статического сервера.

Продуктовый контекст (аудитория, позиционирование, что подтверждено, а что нет) — в `PRODUCT.md`. Всё, что ещё нужно заменить на боевые данные, — в `TODO-CONTENT.md`.

## Запуск

```bash
python3 -m http.server 8080      # или: npx serve .
# → http://localhost:8080/
```

Внешних запросов нет: шрифты и все изображения лежат в репозитории.

### Данные

Все страницы берут лоты из `js/data.js`, поэтому количество квартир, статусы и цены совпадают на главной, в каталоге, шахматке, карточке и на фасаде. Дом — со слов заказчика: блоки А, Б, В, Г по 18 этажей, 1–2 этажи торговые, квартиры с 3-го. Стояк блока — квартира его типового этажа из листов (`js/plans-data.js` подключается раньше `data.js`): А-1…А-8 в блоке А, Б-1…Б-7 в блоках Б и В; площадь, комнатность и экспликация лота — ровно по листу. Листы описывают этажи 3–7 (А) и 3–6 (Б), выше типовой этаж повторяется (у лота `typical: false`); листов блока Г нет — он без квартир. Статусы, цены, отделка и номера генерируются детерминированно (одинаково при каждой загрузке). Под боевые данные:

1. уточнить стояки и этажи `BLD` (планировки этажей выше типовых, блок Г); привязка плоскостей рендеров к блокам (`FACADE[].planes[].blk`) — условная, сетка окон каждой плоскости (`cols`, `from`, `to`) задана калибровкой рендера и от блоков не зависит;
2. заменить генерацию внутри `HOUSE` на разбор выгрузки из отдела продаж (поля лота описаны в коде);
3. обновить `SITE` (телефон, мессенджеры, срок сдачи, часы шоурума, `leadEndpoint`); цены сейчас скрыты — `SITE.showPrices: false` («Цена по запросу», без скидок и фильтра по цене), `true` возвращает их везде.

Цифры (`157 в продаже`, «свободно из 352») считаются из данных; в HTML записаны те же значения, чтобы страница читалась без JavaScript.

### Заявка

Форма (имя, телефон с маской +992, способ связи: звонок / WhatsApp / Telegram / визит в шоурум, выбранная квартира или планировка; объект подставляется сам из `js/object.js`) отправляет JSON методом POST на `/api/lead` — функцию Cloudflare Pages `functions/api/lead.js`. Она пересылает заявку в Telegram (`TG_BOT_TOKEN` + `TG_CHAT_ID`) и/или лидом в Bitrix24 (`BITRIX_WEBHOOK`) — переменные задаются в Cloudflare: Pages → mega-khujand → Settings → Variables and Secrets, в коде ключей нет; посетитель видит «Заявка отправлена». **Пока переменных нет**, функция отвечает 501, и заявка собирается в готовое сообщение, которое посетитель одной кнопкой отправляет в WhatsApp отдела продаж (`SITE.whatsapp`); так же форма ведёт себя на локальном `python3 -m http.server`. Копия заявки остаётся в `localStorage` браузера. Под кнопкой — согласие со ссылкой на `privacy.html`. Кнопки «Записаться на показ» ведут прямо к полям формы. Аналитика: `SITE.metrika` / `SITE.ga` в `js/data.js` — при отправке заявки цель `lead` (Метрика) / событие `generate_lead` (GA). Для проверки состояния ошибки откройте страницу с `?lead=fail`.

Маска телефона: префикс поля «+992 » в номер не входит (раньше его цифры считались номером — при наборе первой цифры поле показывало «+992 99 29»). Вставка «+992…», «00992…», «992…» и номера со скобками и дефисами даёт 9 цифр номера.

### Изображения

Исходники — `media/renders/*.jpg` (рендеры проекта). Сырдарья — `syr-*.jpg` и `aerial-river-2560.jpg`; остальные рендеры в этой папке — дом Гулистон (для Сырдарьи не использовать). Рендеры Сырдарьи пришли в WhatsApp шириной 1080 — для них `tools/images.py` (Pillow, без node): `.venv/bin/python tools/images.py syr-dusk-front …` пишет 640 и 1080 (не больше исходника). Стоковые фото в `media/` остались от первого сайта и на страницах не используются. Происхождение каждого растра записано в файл (`impeccable embed-prompt --read <файл>`; для AVIF — соседний `.json`). Варианты для сайта:

```bash

node tools/images.mjs          # пересобрать media/opt/ (или только часть: node tools/images.mjs retail-storefront-boutiques)

python3 tools/commerce-extract.py # листы 1–2 этажей из media/plans/commerce/src/ → упрощённые схемы SVG
pip install pillow numpy scipy
python3 tools/facade-light.py  # тёмный рендер, слой света и js/facade-light.js
pip install bpy==4.5.4 shapely pymupdf   # Blender как модуль Python 3.11; на Mac с Apple Silicon считает на Metal
python3 tools/model-floor.py                       # чертежи этажей из PDF → media/model/floor.json
python3 tools/model-render.py all /путь/к/сырым    # Cycles: финал, крупные планы, кадры раскладки каждой плиты
python3 tools/model-pack.py /путь/к/сырым          # → media/model/ и js/model-data.js
python3 tools/model-render.py scene /путь/к/сырым  # сцены model-floor-<плита>.blend — открыть в Blender
```

**Макет этажа.** Листов 15, и у каждой серии свой типовой этаж — своя плита макета: А-1…А-8 — этажи 3–7, Б-1…Б-7 — этажи 3–6 (буква — блок; блоки Б и В спроектированы одинаково и показаны вместе, их взаимное расположение неизвестно). `tools/model-floor.py` читает векторный ключ-план каждой плиты из первого листа серии (`media/plans/src/`) и восстанавливает этаж в метрах: стены (чёрные заливки), окна и двери (белые заливки и дуги открывания), балконы, лестницы (марши в обеих ориентациях, площадка — по повороту линии хода), лифты, контуры квартир. Мебель расставлена вручную по 3D-видам из тех же листов — `tools/model-furniture.json`. `tools/model-render.py` (Blender 4.5 как модуль Python) строит макет каждой плиты — стены гипсовые, полы и мебель в цветах 3D-видов из листов (паркет, плитка в санузлах, ткань, дерево, керамика; `MK_PALETTE=plaster` вернёт прежний весь гипс) — и считает в Cycles: финальный кадр с отдельным светом каждой квартиры (группы света), крупный план каждой квартиры и 80 кадров раскладки (у А стопка из пяти этажей, у Б — из четырёх); режимы `final`, `close`, `seq`, `all`, а `anchors` и `close-anchors` пересчитывают только подписи этажей и номера комнат. На Mac с M3 (Metal) финал плиты считается около 20 секунд, крупный план — полторы-две минуты, кадр раскладки — 12–17 секунд, обе плиты целиком — около 80 минут; на 4 ядрах CPU всё в разы дольше. `tools/model-pack.py` поднимает чёрный фон рендера до графита страницы и гасит в него края кадра, сохраняет свет квартир как прибавку к финальному кадру своей плиты (на сайте — сложение «lighter») и пишет `js/model-data.js`. Для новой квартиры впишите её комнаты и мебель в `tools/model-furniture.json` и перезапустите три скрипта.

**Первые два этажа.** Листы 1–2 этажей (торговые помещения) — чистый вектор без квартир и 3D-видов; макет по ним не строится. `tools/commerce-extract.py` перерисовывает каждый лист в упрощённую схему: стены и колонны (тёмно-красная заливка листа) — заливкой, перегородки, окна, двери, лестницы и лифты — линиями; оси (пунктир до кружков), размеры, марки и подписи отбрасываются. Подписи в этих листах нарисованы линиями, а не текстом, поэтому площади залов из экспликаций вписаны в `plans.html` руками. Листа 1-го этажа блока Б нет — для блоков Б и В показан 1-й этаж блока В.

**Свет в окнах.** `tools/facade-light.py` выпрямляет каждую плоскость фасада вечернего рендера (калибровка `FACADE` в `js/data.js`), берёт колонки окон из `PLANES` (размечены вручную, по одной на стояк) и подбирает ряды окон по картинке. Из этой сетки он собирает тёмную версию рендера (окна, горевшие на картинке, выключены), прозрачный слой с тёплым светом во всех окнах и `js/facade-light.js` с четырёхугольником окна для каждой ячейки «секция:этаж:стояк». На сайте свет рисуется на холсте только в окнах нужных квартир. Если поменяется рендер или нарезка секций, поправьте `PLANES` и перезапустите скрипт.

Герой — `facade-night-dark` 1920 px AVIF ≈ 120 КБ, предзагружается только он (и два файла Unbounded); остальное грузится лениво.

**Карта места.** `tools/map-build.py <папка-кэша>` качает куски OpenStreetMap вокруг дома (≈20 МБ XML, кэш вне репозитория) и рисует подложку `media/map/khujand.svg` в цветах сайта: река с штриховкой, зелень точками, дома, улицы по классам, мосты — без подписей (≈130 КБ, со сжатием ≈45 КБ). Подписи, номера, кольца и Сырдарьинская — поверх, в HTML и маленьком SVG; координаты скрипт печатает, в `index.html` они вписаны руками. Точка дома — по Google Картам; 14-й дом — на чётной, речной стороне улицы (нечётные номера в OSM — на северной). Подпись «© участники OpenStreetMap» на карте обязательна (ODbL).

## Качество

- Доступность: `lang="ru"`, skip-ссылки, landmarks, видимый фокус, клавиатура в шахматке (стрелки, Home/End, PageUp/PageDown), на фасаде (стрелки, Enter) и в слайдерах; диалоги возвращают фокус; axe-core (WCAG 2.2 AA) — без нарушений; вторичный текст ≥ 4.5:1.
- Движение: сцены обновляются одним `requestAnimationFrame` на кадр по скроллу и ресайзу, активны только видимые (IntersectionObserver). Появление при прокрутке — `MK.motion` в `js/site.js`: рендеры «включаются» из темноты, заголовки выходят из-под плиты, строки списков и номера на рендерах встают по очереди. `prefers-reduced-motion` отключает закрепление героя, пролёт сквозь буквы и все появления: плита и макет идут друг за другом, окна загораются сразу. Раскладка этажей (`js/model.js`) от 900 px идёт по прокрутке (кадры подгружаются сжатыми после загрузки страницы, сначала каждый 16-й; расшифрованы вне основного потока только ~15 кадров рядом с текущим, поэтому память и прокрутка не зависят от длины раскладки), на телефоне играет один раз, при уменьшенном движении и в режиме экономии трафика показывается финальный кадр со светом.
- Без JavaScript: весь текст главной читается, внутренние страницы показывают, как связаться с отделом продаж.
- Сеть: `MK.net` в `js/site.js` (`lite` — экономия трафика или 2G, `slow` — ещё и 3G). Кадры раскладки не грузятся до загрузки страницы, на медленной сети — только у самого экрана, при `lite` — один финальный кадр; встроенный подбор в шахматке на медленной сети ждёт кнопки; крупные кадры окна на карточке квартиры — после загрузки страницы. Соседние страницы подгружаются при наведении (`speculationrules`), переход между страницами — плавный (`@view-transition`, шапка стоит на месте). Рендер «включается», когда картинка уже пришла. На медленном 4G (1,6 Мбит/с, 150 мс) со сжатием: главная на телефоне — ≈470 КБ и 20 запросов до загрузки (было 1,2 МБ и 70), загрузка ≈2,7 с.
- Хостинг: включите gzip или brotli для HTML, CSS, JS и SVG (стили — 115 КБ → 25 КБ, ключ-план этажа — 285 КБ → 59 КБ) и долгий кэш для `media/` и `fonts/`.
- SEO: `title`, `description`, Open Graph, favicon, JSON-LD на главной (с адресом и координатами), `robots.txt`.

## Публикация

Сайт опубликован на Cloudflare Pages (проект `mega-khujand`): **https://mega-khujand.pages.dev**

`bash tools/build-dist.sh` собирает папку `dist/` (в git её нет) — только то, что нужно сайту: страницы, `css/`, `js/`, `fonts/`, `media/{opt,light,plans,model,map}`, `media/og.jpg`, `robots.txt`, `sitemap.xml`, `_headers`. Заметки (`*.md`), `tools/`, `design-reference/`, `calibration/`, рендеры, сырые кадры макета и стоковые фото в неё не попадают. `_headers` задаёт кэш (шрифты — год, `media/` — неделя, HTML/CSS/JS — без долгого кэша) и заголовки безопасности.

Обновить сайт после правок:

```bash
bash tools/build-dist.sh && npx wrangler@latest pages deploy dist --project-name mega-khujand --branch main
```

Первый раз нужен вход в Cloudflare: `npx wrangler@latest login` (откроется браузер, «Allow»).

**Свой домен.** Cloudflare → Workers & Pages → проект → Custom domains. После подключения замените адрес `https://mega-khujand.pages.dev` на новый в `og:image`, `og:url` и `canonical` всех страниц (`flat.html` и `404.html` — только `og:image`), в `sitemap.xml` и в строке `Sitemap:` файла `robots.txt`, затем опубликуйте заново.
