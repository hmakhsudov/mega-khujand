# MEGA KHUJAND — сайт жилого комплекса

Продажный сайт ЖК MEGA KHUJAND на набережной Сырдарьи в Худжанде. Статический HTML, одна общая таблица стилей и небольшой скрипт на страницу — без фреймворка и без сборки. Открывается с любого статического сервера.

Продуктовый контекст (аудитория, позиционирование, что подтверждено, а что нет) — в `PRODUCT.md`. Всё, что ещё нужно заменить на боевые данные, — в `TODO-CONTENT.md`.

## Запуск

```bash
python3 -m http.server 8080      # или: npx serve .
# → http://localhost:8080/
```

Внешних запросов нет: шрифты и все изображения лежат в репозитории.

## Страницы

| Файл | Что делает для покупателя |
|------|---------------------------|
| `index.html` | Главная «Выставочный макет»: гипсовая плита с вырезанным именем, сквозь буквы — дом в сумерках; от 900 px прокрутка пролетает сквозь буквы, и на фасаде загораются окна свободных квартир (клавиши по числу спален, бирка с ценой). Затем «Типовой этаж изнутри»: гипсовый макет этажей 3–6 раскрывается по прокрутке, верхние этажи снимаются, и в квартирах с планировками по очереди загорается свет (наведение — бирка и ссылка на планировку). Дальше — планировки с реальными количествами, стенд материалов, легенда квартала и двора, указатель сервиса, шоурум и форма заявки |
| `plans.html?plan=…` | Планировки из проекта: 3D-вид из листа или «Макет» (гипсовая квартира с мебелью) с номерами помещений, экспликация (номера совпадают с планом), место квартиры на этаже — гипсовый макет со светом в выбранной квартире или схема из листа (обе кликабельны), фильтр по комнатности, «Увеличить», «Отправить планировку», лист в PDF, заявка с выбранной планировкой; `?rooms=1` — фильтр |
| `flats.html` | Каталог: комнатность, цена/площадь/этаж (двойные слайдеры), корпус, отделка, терраса/река/угловая, только свободные, избранное; плитка и строки; состояние фильтров в адресе (`?rooms=2&price=…`) |
| `flat.html?id=…` | Карточка квартиры: статус, цена, планировка, характеристики, площади помещений, похожие; форма с этой квартирой; для неверного `id` — страница восстановления |
| `building.html` | Шахматка корпус → секция → стояк → этаж: клавиатурная сетка, карточка лота в диалоге, ссылки `?id=` и `?corp=&sect=` |
| `picker.html` | Подбор на фасаде: подсветка окон на рендере из тех же лотов, ракурсы «днём» (корпус 1) и «вечером» (корпус 2, по умолчанию), стрелки на клавиатуре; `?v=day|dusk`, `?rooms=0…4`, `?id=…`; `?embed=1` для встраивания |
| `404.html` | Страница «не найдено» для статического хостинга |

«Забронировать» в шахматке и на фасаде ведёт на `flat.html?id=…#lead` — форма уже содержит выбранную квартиру.

media/plans/          SVG-заглушки для каталога и шахматки; media/plans/light/ — версии для гипсовых подложек. Площади помещений на чертежах не подписаны: единственный источник — таблица на странице квартиры

### Данные

Все страницы берут лоты из `js/data.js`, поэтому количество квартир, статусы и цены совпадают на главной, в каталоге, шахматке, карточке и на фасаде. Сейчас лоты генерируются детерминированно из `BLD` (одинаково при каждой загрузке). Под боевые данные:

1. заменить `BLD` на реальную нарезку дома (секции 1–3 корпусов 1 и 2 должны совпадать с сеткой окон на рендерах — см. `FACADE`);
2. заменить генерацию внутри `HOUSE` на разбор выгрузки из отдела продаж (поля лота описаны в коде);
3. обновить `SITE` (телефон, срок сдачи, шоурум, `leadEndpoint`).

Цифры на главной (`832`, `365 в продаже`, «от 292 000 смн») считаются из данных; в HTML записаны те же значения, чтобы страница читалась без JavaScript.

### Заявка

Форма (имя, телефон с маской +992, способ связи: звонок / WhatsApp / Telegram / визит в шоурум, выбранная квартира) отправляет JSON методом POST на `SITE.leadEndpoint`. **Пока адрес пуст, форма работает в демонстрационном режиме** и сохраняет заявки только в `localStorage` браузера — перед запуском подключите приёмник. Для проверки состояния ошибки откройте страницу с `?lead=fail`.

### Изображения

Исходники — `media/renders/*.jpg` (рендеры проекта). Стоковые фото в `media/` остались от первого сайта и на страницах не используются. Происхождение каждого растра записано в файл (`impeccable embed-prompt --read <файл>`; для AVIF — соседний `.json`). Варианты для сайта:

```bash
npm i --no-save sharp
node tools/images.mjs          # пересобрать media/opt/
sh tools/plans-light.sh        # пересобрать media/plans/light/ после замены заглушек
pip install pymupdf pillow numpy
python3 tools/plans-extract.py # новые листы из media/plans/src/ → media/plans/real/ и js/plans-data.js
pip install pillow numpy scipy
python3 tools/facade-light.py  # тёмный рендер, слой света и js/facade-light.js
pip install bpy==4.5.4 shapely pymupdf   # Blender как модуль Python 3.11
python3 tools/model-floor.py                       # чертёж этажа из PDF → media/model/floor.json
python3 tools/model-render.py all /путь/к/сырым    # Cycles: финал, крупные планы, кадры раскладки
python3 tools/model-pack.py /путь/к/сырым          # → media/model/ и js/model-data.js
```

**Гипсовый макет этажа.** `tools/model-floor.py` читает векторный ключ-план типового этажа из листа проекта (`media/plans/src/`) и восстанавливает этаж в метрах: стены (чёрные заливки), окна и двери (белые заливки и дуги открывания), балконы, лестницу, лифты, контуры квартир Б-1…Б-5. Мебель расставлена вручную по 3D-видам из тех же листов — `tools/model-furniture.json`. `tools/model-render.py` (Blender 4.5 как модуль Python) строит гипсовый макет и считает в Cycles: финальный кадр с отдельным светом каждой квартиры (группы света), крупный план каждой квартиры и 80 кадров раскладки; режимы `final`, `close`, `seq`, `all`, а `anchors` и `close-anchors` пересчитывают только подписи этажей и номера комнат. На 4 ядрах CPU финал и крупный план считаются около 8 минут каждый, кадр раскладки — около минуты (все 80 — примерно полтора часа). `tools/model-pack.py` поднимает чёрный фон рендера до графита страницы и гасит в него края кадра, сохраняет свет квартир как прибавку к финальному кадру (на сайте — сложение «lighter») и пишет `js/model-data.js`. Когда придут остальные листы, впишите комнаты новых квартир в `tools/model-furniture.json` и перезапустите три скрипта.

**Свет в окнах.** `tools/facade-light.py` выпрямляет каждую плоскость фасада вечернего рендера (калибровка `FACADE` в `js/data.js`), берёт колонки окон из `PLANES` (размечены вручную, по одной на стояк) и подбирает ряды окон по картинке. Из этой сетки он собирает тёмную версию рендера (окна, горевшие на картинке, выключены), прозрачный слой с тёплым светом во всех окнах и `js/facade-light.js` с четырёхугольником окна для каждой ячейки «секция:этаж:стояк». На сайте свет рисуется на холсте только в окнах нужных квартир. Если поменяется рендер или нарезка секций, поправьте `PLANES` и перезапустите скрипт.

Герой — `facade-night-dark` 1920 px AVIF ≈ 120 КБ, предзагружается только он (и два файла Unbounded); остальное грузится лениво.

## Качество

- Доступность: `lang="ru"`, skip-ссылки, landmarks, видимый фокус, клавиатура в шахматке (стрелки, Home/End, PageUp/PageDown), на фасаде (стрелки, Enter) и в слайдерах; диалоги возвращают фокус; axe-core (WCAG 2.2 AA) — без нарушений; вторичный текст ≥ 4.5:1.
- Движение: сцены обновляются одним `requestAnimationFrame` на кадр по скроллу и ресайзу, активны только видимые (IntersectionObserver). Появление при прокрутке — `MK.motion` в `js/site.js`: рендеры «включаются» из темноты, заголовки выходят из-под плиты, строки списков и номера на рендерах встают по очереди. `prefers-reduced-motion` отключает закрепление героя, пролёт сквозь буквы и все появления: плита и макет идут друг за другом, окна загораются сразу. Раскладка этажей (`js/model.js`) от 900 px идёт по прокрутке (кадры подгружаются сжатыми после загрузки страницы, сначала каждый 16-й; расшифрованы вне основного потока только ~15 кадров рядом с текущим, поэтому память и прокрутка не зависят от длины раскладки), на телефоне играет один раз, при уменьшенном движении и в режиме экономии трафика показывается финальный кадр со светом.
- Без JavaScript: весь текст главной читается, внутренние страницы показывают, как связаться с отделом продаж.
- SEO: `title`, `description`, Open Graph, favicon, JSON-LD на главной, `robots.txt`.
